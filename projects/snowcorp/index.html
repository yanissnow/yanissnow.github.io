THE BRIEF

Give a fictional company
a working Windows network.

SnowCorp has three departments: IT, HR and Sales. I built an isolated domain, created employee identities, separated department file access, and tested selected security controls. Each result was documented through screenshots, recordings and written records.

  • Domain joining and a healthy computer secure channel.
  • All nine department-access tests matched expectations.
  • Lockout, administrator recovery and automatic locking tested.
  • Deleted file restored with an identical SHA-256 hash.

02Connect and troubleshoot the lab networkSESSION 02 · 13 Oct 2026+

Give both machines predictable addresses and verify communication with the firewall enabled.

  1. Saved CLIENT01's clean-install recovery snapshot. Installed available Windows updates and verified the clocks and time zones.
  2. Connected both VM adapters to the internal network SnowCorp-LAN, with the virtual cables connected.
  3. Set DC01 to 10.10.10.10/24 and CLIENT01 to 10.10.10.20/24. Set preferred DNS to 10.10.10.10 on both; left gateway and alternate DNS blank.
  4. Investigated failed ping using the configured addresses, repeated tests and CLIENT01's ARP cache. An ARP entry existed even while ping timed out.
  5. Created scoped inbound ICMPv4 Echo Request rules for the other lab machine's address on each VM. Kept Windows Firewall enabled.
  6. Retested ping in both directions. Each test returned 4 replies from 4 requests, with 0% loss.

06Create and test department sharesSESSION 06 · 19 Oct 2026+

Allow employees to use their own department's files while keeping the other departments separate.

  1. Saved 04-Users-and-Groups-Ready snapshots. Created IT, HR and Sales folders under C:\SnowCorp-Shares on DC01.
  2. Disabled NTFS inheritance, converted the inherited entries and removed broad Users and CREATOR OWNER access.
  3. Retained Administrators and SYSTEM with Full control. Granted the corresponding department group Modify on the folder, subfolders and files.
  4. Shared the folders as \\DC01\IT, \\DC01\HR and \\DC01\Sales. Removed Everyone; granted Administrators Full Control and the department group Change and Read.
  5. Tested all nine employee-to-share combinations. Each employee could create a file in their own department and was denied access to both other departments.
  6. Recorded a short demonstration of James accessing Sales and being denied HR access.

09Delete, restore and verify a test fileSESSION 09 · 26 Oct 2026+

Prove that a file can be restored from a copy outside the VM disks with unchanged contents.

  1. As Alex on CLIENT01, created a five-line test file in the IT share under Backup-Restore-Test and calculated its original SHA-256 hash.
  2. Copied it through a temporary VirtualBox shared folder to the laptop's 08-Backup-and-Restore folder. Saved the original hash record.
  3. Verified the backup hash from CLIENT01 and separately from host PowerShell.
  4. Deleted only the dedicated source test file. Test-Path returned False.
  5. Restored the laptop backup to the original share path. Test-Path returned True and Get-Content displayed the original five lines.
  6. Compared restored and original SHA-256 values, saved both CSV records and a True comparison result, removed the temporary mapping and shut down both VMs.
  7. Created Backup-and-Restore-Verified snapshots on both VMs and saved their evidence.
Get-FileHash -LiteralPath $sourceFile -Algorithm SHA256
Test-Path -LiteralPath $sourceFile
Get-Content -LiteralPath $sourceFile
RESULT / WHAT WAS VERIFIEDOriginal, laptop backup and restored-file hashes matched. This was file-content recovery on the same physical laptop, not a system-state or off-device disaster-recovery test.

WHAT I LEARNED

A setting needs a test.

  • A failed ping needs investigation. Addressing, ARP and firewall behavior provide different pieces of evidence.
  • Share and NTFS permissions must be checked together, using the intended employee account.
  • A delay message does not prove account lockout. Confirm the account state and relevant events.
  • A restore is more convincing when the recovered file’s hash matches the saved original.
SCOPE / LIMITS

A controlled personal lab.

This was a two-VM learning environment with fictional users and deliberately generated security events. It was not an enterprise deployment.

The restore test covered one file’s contents. Its backup remained on the same physical laptop. System-state recovery, high availability, automatic account unlocking and several password-policy behaviors were outside the verified tests.

The report distinguishes configured values from behavior that was actually tested.
