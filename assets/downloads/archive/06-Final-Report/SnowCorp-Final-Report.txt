PROJECT OVERVIEW
Built a small Windows company network for SnowCorp, a fictional
organization with IT, HR, and Sales departments.

The project covered domain administration, employee accounts,
department file access, security policies, support troubleshooting,
Windows Security-event investigation, PowerShell reporting,
and verified file backup and restoration.

Configuration and testing were documented through screenshots,
short recordings, a work journal, two support tickets,
a security investigation report, scripts, and exported results.

All scenarios were performed in an isolated personal lab.

SUPPORT TROUBLESHOOTING
Documented two formal tickets retrospectively from the recorded
lab exercises.

SC-IT-001 — Ping connectivity
CLIENT01 initially failed to receive ping replies from DC01.

Checked computer identities, static addressing, the virtual
network configuration, repeated ping results, and the ARP cache.

Added restricted inbound ICMPv4 Echo Request rules:
DC01 allowed requests from 10.10.10.20 to 10.10.10.10.
CLIENT01 allowed requests from 10.10.10.10 to 10.10.10.20.

Retests succeeded in both directions:
4 packets sent, 4 received, 0% loss.

Windows Firewall remained enabled.
Follow-up checks verified the rules' direction, action,
ICMP type, profiles, and address restrictions.

The successful retry after the firewall change supports ICMP
filtering as the explanation for the repeated timeouts.
The cause of an earlier Destination host unreachable message
was not separately established.

SC-IT-002 — Controlled account lockout
policy.test could not sign in after deliberately incorrect
password submissions.

Distinguished an initial sign-in delay from an explicit lockout.
Confirmed the locked state separately in Active Directory.
An administrator unlocked the account and successful sign-in
was verified on CLIENT01.

The account-lockout policy was retained.
The test account was disabled after the exercise.

SCOPE AND LIMITATIONS
This was an isolated personal training lab with fictional users.
The security events were deliberately generated during tests.

A single domain controller also hosted the department shares.
The project did not test high availability or enterprise-scale
deployment.

The backup exercise verified recovery of one file's contents.
It did not test restoration of NTFS permissions, AD system state,
or complete servers or VMs.

The file backup is outside the VM disks but remains on the
same laptop's physical storage. Recovery from a separate
physical device or cloud backup was not tested.

Snapshots provide recovery points and do not replace backups.

The 15-minute automatic account unlock, exact failed-attempt
count, and individual password-history, complexity, and age
behaviors were not separately tested.

Employee passwords were changed before the later 14-character
minimum was configured. Their existing lengths were not verified.

Windows evaluation editions were used.
Screenshots, reports, scripts, and recordings document the
completed work independently of the VMs' future availability.
