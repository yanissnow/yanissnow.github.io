IT Support and Security Lab — Security Investigation

CASE
Case ID: SC-SEC-001
Company: SnowCorp (fictional)
Type: Controlled lab exercise
Investigation dates: October 20 and October 25, 2026
Report date: October 25, 2026
Displayed event times: Eastern Daylight Time (UTC-04:00)

GOAL
Investigate a domain account lockout and administrator unlock, correlate
a controlled failed sign-in across the workstation and domain controller,
and preserve the relevant Windows Security logs outside the VMs.

SUMMARY
Reviewed the October 19 lockout and administrator unlock of policy.test.
On October 25, submitted one deliberately incorrect password on CLIENT01
and correlated the resulting failed-logon and Kerberos failure records.
The matching account, source address, timestamps, and failure codes
support an incorrect-password explanation for the controlled attempt.

Preserved three EVTX exports on the laptop and checked their filenames,
sizes, and readability. Disabled policy.test after testing.

ENVIRONMENT
Domain: snowcorp.test
NetBIOS name: SNOWCORP
Domain controller: DC01.snowcorp.test / 10.10.10.10
Workstation: CLIENT01.snowcorp.test / 10.10.10.20
Network: SnowCorp-LAN / isolated VirtualBox internal network
Test account: SNOWCORP\policy.test
Test account location: SnowCorp/Employees/IT
Department group membership: None assigned

AUDITING PREPARATION
Created SnowCorp-DC-Auditing and linked it to the Domain Controllers OU.

Configured Success and Failure auditing for:
Audit Credential Validation
Audit Kerberos Authentication Service
Audit User Account Management
Audit Logon

Enabled the security option that forces audit subcategory settings
to override audit category settings.

Applied computer policy with gpupdate. Verified the effective settings
using auditpol and confirmed GPO application using gpresult.
CLIENT01 already had Success and Failure auditing for Logon.

ANALYSIS
The October 25 records concern the same account and occur one second
apart. DC01 identifies CLIENT01's planned IP address, while CLIENT01
records the failed interactive sign-in. Both failure codes support
the deliberately incorrect password used in the test.

The October 19 lockout is a separate earlier test. Event 4740 records
the lockout, and event 4767 identifies the administrator's unlock action.
The Audit Success label on those account-management records describes
the recorded management action, not a successful user sign-in.

The reviewed activity was deliberately generated in the lab. It is
documented as controlled testing rather than an observed external attack.

EXPORT AND TRANSFER VERIFICATION
Installed Guest Additions inside CLIENT01 and verified VBoxService
was running. Used a temporary VirtualBox shared folder to transfer
CLIENT01's export and both DC01 exports to the laptop.

The initial CLIENT01 export path omitted the backslash after C:,
placing its folder under the PowerShell working directory.
Located the existing export under C:\Windows\System32 and copied it
from its actual absolute path. Corrected a mistyped VBOXSVR name
during transfer. The original export was retained.

Confirmed all three filenames and sizes on the laptop.
Used Get-WinEvent to read one event from each saved file successfully.
This was a readability check, not a review of every exported event.

CLEANUP
Verified policy.test had Enabled: False and LockedOut: False.
Removed the temporary SnowCorpEvidence shared-folder connection.
Confirmed both VMs were shut down after the practical work.

LIMITATIONS
